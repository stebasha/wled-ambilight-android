# WLED Ambilight для Android / Android TV

Локальное приложение фоновой подсветки: анализирует периметр экрана и передаёт цвета на
LED-контроллер с прошивкой [WLED](https://kno.wled.ge/) по DDP или WLED UDP. Работает на
смартфонах, планшетах, Android TV и Google TV.

> Статус: MVP. Автоматические проверки (unit-тесты, `assembleDebug`, `lintDebug`, `assembleRelease`)
> выполнены; проверка на реальном WLED, Android TV и с DRM-контентом требует оборудования и описана
> в [TESTING.md](TESTING.md). См. раздел «Фактически проверено».

## Возможности

- Поиск контроллеров по mDNS (`_wled._tcp`), явно запускаемое сканирование локальной сети /24,
  ручное добавление IP/hostname.
- Проверка HTTP JSON API WLED (`/json/info`), отображение версии прошивки и количества LED.
- Тест цвета по HTTP и по realtime-протоколу.
- Захват экрана через системный MediaProjection с обязательным согласием и foreground service
  (`mediaProjection`) с уведомлением и кнопкой «Стоп».
- Анализ четырёх сторон экрана: количество LED на сторону, угол первого LED, направление обхода,
  реверс отдельных сторон, толщина анализируемой полосы, отступ от края, вес края.
- Яркость, насыщенность, гамма, баланс RGB, минимальная яркость, компенсация чёрных полос.
- Профили сглаживания Off / Fast / Balanced / Smooth / Custom с разными параметрами EMA, порогом
  изменения и ограничением шага.
- Профили производительности: экономия, баланс, плавность, минимальная задержка.
- Realtime-протоколы: **DDP** (UDP 4048, RGB888) и **WLED UDP Realtime** (WARLS, DRGB, DNRGB,
  порт по умолчанию 21324). Packet-level unit-тесты.
- Диагностика: HTTP-проверка, тестовые цвета, FPS, время анализа/отправки, пакеты/с, пропущенные
  кадры, детект чёрного кадра, журнал типизированных событий, экспорт отчёта без содержимого экрана.
- Тёмная и AMOLED-чёрная тема, английский и русский языки (системный).
- D-pad-навигация, видимый фокус, адаптивная навигация (нижняя панель / боковая панель на TV).
- **Зоны (0.2.0):** дополнительные ленты в одной системе с экраном — под столом (нижний край),
  боковые арки и колонны (левый/правый край), второй экран или арка по периметру, подсветка по
  среднему цвету области. Зона может быть диапазоном того же WLED (например, LED 76–135) или
  отдельным контроллером. Все зоны считаются из одного кадра и отправляются синхронно.
- **Лампы Govee** через официальный Govee LAN API (UDP 4003): поиск, ручное добавление, один цвет
  выбранной области экрана на лампу.
- **Управление WLED:** питание, яркость контроллера, пресеты и эффекты, выход из realtime.
- **Демо-режим** без захвата экрана, импорт/экспорт профиля через буфер обмена.

## Чего приложение не делает

- Не обходит DRM и защищённые поверхности. Если видео в DRM-сервисе чёрное — это ограничение
  Android, а не WLED. Для гарантированной подсветки защищённого контента нужен внешний HDMI-захват.
- Не поддерживает Hyperion/HyperHDR и USB Adalight в этой версии.
- Не отправляет кадры, телеметрию или секреты в сеть/облако.
- Не работает как сервер. Единственное исключение: явно запущенный поиск Govee слушает UDP 4002
  три секунды, потому что так устроен ответ Govee LAN API.
- Не управляет посегментно лампами Govee и не поддерживает Philips Hue / Nanoleaf / WiZ / Yeelight.

## Требования

- Android 8.0 (API 26) и новее; targetSdk 35.
- Телефон/планшет или Android TV / Google TV.
- WLED 0.13+ в той же локальной сети (HTTP API включён; для mDNS — соответствующий пункт в WLED).
- Для сборки: JDK 17, Android SDK Platform 35, Build-Tools 35.0.0. Gradle поставляется wrapper-ом
  (8.13).

## Сборка

```powershell
# Windows (PowerShell): скрипт сам подставит JDK/SDK из .tools, если они там лежат
.\scripts\build.ps1 assembleDebug

# или вручную
$env:JAVA_HOME = "C:\path\to\jdk-17"
$env:ANDROID_HOME = "C:\path\to\android-sdk"
.\gradlew.bat assembleDebug
```

`local.properties` должен указывать на SDK:

```properties
sdk.dir=C:/path/to/android-sdk
```

APK: `app/build/outputs/apk/debug/app-debug.apk` (debug-вариант имеет суффикс `dev.wledambilight.debug`).

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Release-сборка: `.\gradlew.bat assembleRelease`. APK по умолчанию **неподписан**; ключ владельца
проекта не хранится в репозитории.

Если системный `%TEMP%` недоступен для записи, задайте `TEMP`/`TMP` в каталог проекта — это
требование Kotlin/Gradle, не приложения.

## Запуск

1. Подключите телефон/TV к той же сети, что и WLED.
2. «Устройства» → «Поиск по mDNS» или «Добавить вручную» (например, `192.168.1.50`, HTTP 80).
3. Нажмите «Проверить»: приложение запросит `/json/info` и покажет версию и число LED.
4. «Калибровка»: задайте LED по сторонам, угол первого LED, направление, реверс.
5. «Цвет»: настройте яркость, насыщенность, гамму и сглаживание.
6. «Ambilight» → «Запустить»: подтвердите системный захват экрана.

Остановить можно кнопкой в приложении, кнопкой «Стоп» в уведомлении или системной остановкой
проекции. WLED также выходит из realtime-режима по таймауту пакетов (2 с).

## Известные ограничения

- UDP не гарантирует доставку; при потере Wi-Fi сессия завершается с диагностикой.
- mDNS часто блокируется в гостевых сетях, VLAN и при client isolation; остаётся ручной ввод и скан /24.
- Количество LED ограничено 1500; DRGB не адресует больше 480 LED (используйте DNRGB или DDP).
- WLED должен быть в режиме, допускающем realtime; другой realtime-источник перекрывает вывод.
- Захват экрана на Android 14+ требует запуска foreground service до `getMediaProjection` — это
  реализовано, но прошивки производителей могут дополнительно ограничивать автозапуск.
- Приложение не переопределяет язык внутри себя; язык берётся из системы.
