# Changelog

## 0.4.4 — без периодического мерцания Govee

- Лампа мерцала каждые 5 с, с тем же периодом, что и повтор команды включения razer. Команда теперь
  отправляется только в начале сеанса (три раза, подтверждений нет): режим держат сами кадры.

## 0.4.3 — меньше мерцания Govee

- Включение режима razer повторяется раз в 30 с вместо 5 с: частый повтор мог вызывать мерцание.

## 0.4.2 — сегменты подтверждены на H60B0

- На настоящей H60B0 razer-кадры работают только с выключенным растягиванием (`flag = 0`), а с
  `flag = 1` лампа их игнорирует. Растягивание теперь выключено по умолчанию, а для H60B0 всегда
  выключено и скрыто в настройках.

## 0.4.1 — сегменты H60B0

- Для Govee H60B0 посегментный режим по умолчанию предлагает 8 сегментов: столько сообщает Govee
  Platform API. Остальные модели начинают с 10, число можно изменить.

## 0.4.0 — сегменты Govee (экспериментально)

- Зона Govee с привязкой «Край экрана» может работать посегментно: число сегментов (2–100)
  распределяется вдоль края, есть обратное направление и растягивание на всю лампу.
- Используется неофициальный режим razer/DreamView (UDP 4003, до 40 кадров/с). Govee его не
  документирует, а лампа не подтверждает приём, поэтому поддержка конкретной модели проверяется
  только глазами: «Тест» на карточке зоны на 10 с показывает белый первый сегмент и полосы красного,
  зелёного и синего.
- В конце сеанса лампа возвращается в прежнее состояние. Режим один цвет работает как раньше.

## 0.3.1 — выбор разрешения захвата

- «Настройка» → «Цвет» → «Разрешение захвата»: Авто, 160×90, 240×135, 320×180, 480×270 (для 16:9;
  вторая сторона следует пропорциям экрана). «Авто» берёт 160 px до 150 LED и 320 px для длинных
  лент, не выше профиля производительности; ручной выбор важнее профиля.

## 0.3.0 — Home Assistant, чёрный кадр

### Исправлено

- **HTTP к WLED на Android 9+:** в манифесте не было разрешения незашифрованного HTTP, поэтому
  система отклоняла `/json/info`, пресеты и эффекты. Добавлен `network_security_config`
  (cleartext для локальной сети, HTTPS по системным сертификатам). UDP-поток это не затрагивало.

### Добавлено

- **Home Assistant** как выход: сервер (адрес, порт 8123, HTTPS, долгосрочный токен), список
  цветных светильников `light.*` из `/api/states`, привязка светильника к области или краю экрана в
  редакторе зон. Отправка `light.turn_on` (`rgb_color` + `brightness`, `transition` 0.3 с) или
  `light.turn_off` для чёрного; не чаще 4 раз/с на светильник, без блокировки конвейера, с паузой
  при ошибках. Токен хранится отдельно от списка устройств и не попадает в профиль и журнал.
- **Порог чёрного** (0–25 % яркости): зоны темнее порога выключаются, а не светятся тусклым цветом.
- **Поведение при чёрной картинке** (DRM, чёрный экран, пауза) через 1.5 с: выключить, держать
  последние цвета или показать резервный цвет (5 вариантов) на всех выходах.

## 0.2.0 — зоны, Govee, новый интерфейс

### Исправлено

- **Ориентация ленты:** анализ кадра читал нижнюю и левую стороны в обратном направлении
  относительно схемы `LedLayoutMapper`; при монтаже по часовой стрелке цвета снизу и слева шли
  зеркально. Превью калибровки нижней стороны тоже было зеркальным. Добавлены регрессионные тесты
  (`OrientationTest`).
- **Keep-alive:** на статичной картинке MediaProjection не присылает новых кадров, и WLED выходил из
  realtime через ~2.5 с. Теперь последний кадр повторяется раз в секунду.
- **Выход из realtime:** при остановке приложение отправляет `{"live": false}`, WLED сразу
  возвращается к своему эффекту/пресету.

### Добавлено

- **Зоны:** дополнительные ленты синхронно с экраном — вдоль края (стол → низ, боковые арки →
  лево/право), по периметру (второй экран, арка), среднее по области. Зона может жить на том же
  контроллере (смещение первого LED, DDP offset / DNRGB start) или на другом WLED. Пересечения и
  ограничения протоколов (DRGB — один диапазон с LED 0, WARLS — до 255) проверяются `OutputPlanner`
  и показываются в редакторе.
- **Govee LAN API:** поиск (`scan`, multicast 239.255.255.250:4001, ответ на UDP 4002 только 3 с по
  нажатию), ручное добавление, вывод `colorwc` на UDP 4003 с ограничением частоты (≤ 10/с) и
  пропуском почти одинаковых цветов. Лампа показывает один цвет области экрана.
- **Управление WLED:** питание, яркость контроллера, пресеты (`/presets.json`), эффекты
  (`/json/eff`), выход из realtime.
- **Демо-режим** без захвата экрана: синтетическая анимация через весь конвейер (превью и, если
  настроены, реальные ленты).
- **Профили:** копирование/вставка JSON-профиля (раскладка, цвет, зоны) через буфер обмена.
- Устойчивость: у каждого выхода свой счётчик ошибок и экспоненциальная пауза (1→15 с); сессия
  завершается с `NETWORK_LOST`, только если недоступны все выходы. При повторе адрес хоста
  резолвится заново (смена IP).
- Производительность: захват без промежуточного `ByteArray` на кадр (кольцо из 4 буферов, массовое
  чтение строк), кеш зон в анализаторе, превью обновляется не чаще 20 раз/с.

### Интерфейс

- Новая тема (тёплый янтарь → коралл → фиолет на глубоком ночном фоне), карточки с иконками,
  крупная круглая кнопка старт/стоп, «свечение» главного экрана от текущих цветов ленты.
- Навигация из 5 пунктов: Главная, Устройства, Зоны, Настройка (Раскладка/Цвет), Ещё
  (Управление WLED, Диагностика, Настройки). На TV и планшете — боковая панель с отступами под
  overscan.
- Схема источника зоны, живые полоски цветов каждой зоны, степперы ±10 для длинных лент.

## 0.1.0 — MVP

Первая рабочая версия.

### Добавлено

- Onboarding, главный экран, устройства, калибровка, цвет/сглаживание, диагностика, настройки.
- Ручное добавление WLED, mDNS-поиск `_wled._tcp`, явный скан локальной /24.
- WLED HTTP JSON API: проверка `/json/info`, версия, число LED, HTTP-тест цвета.
- MediaProjection через foreground service, уведомление с остановкой, обработка системного стопа.
- Анализ периметра экрана с учётом угла, направления, реверса сторон и толщины полосы.
- Цветовой конвейер: яркость, насыщенность, гамма, баланс RGB, минимальная яркость, компенсация
  чёрных полос.
- Сглаживание Off/Fast/Balanced/Smooth/Custom и профили производительности.
- Протоколы DDP и WLED UDP (WARLS, DRGB, DNRGB) с packet-level тестами.
- Диагностика: FPS, задержки, пакеты, пропущенные кадры, чёрный кадр, журнал и экспорт.
- Тёмная/AMOLED-тема, английский и русский языки, D-pad-навигация и адаптивная навигация.

### Известные ограничения

- Hyperion/HyperHDR и USB Adalight не поддерживаются.
- DRM-контент может быть чёрным; обход не реализован.
- IPv6 и RGBW-коррекция не реализованы.
- Govee: один цвет на лампу (посегментный стрим не входит в опубликованный LAN API).
- Проверка на реальном WLED/Govee/Android TV требует оборудования.
