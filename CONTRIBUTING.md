# Участие в разработке

## Стиль кода

- Kotlin, официальный стиль, 4 пробела, без wildcard-импортов.
- Чистое ядро (`core/imaging`, `core/protocol`) не должно зависеть от Android: это позволяет гонять
  быстрые JVM-тесты и переиспользовать код.
- Пользовательские строки — только в `res/values/strings.xml` и `values-ru/strings.xml`.
- Сетевые вызовы — с таймаутами, отменой и лимитом ответа. Новые протоколы обязаны иметь
  packet-level тесты.
- Не добавляйте разрешения и библиотеки без обоснования в PR/коммите.

## Ветки и коммиты

- Ветка на функцию: `feature/...`, `fix/...`.
- Коммит в императиве, коротко: `Add DNRGB chunking tests`.
- В одном коммите — одна логическая правка; форматирование отдельно.

## Обязательные проверки перед PR

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Для изменений UI/протоколов:

```bash
./gradlew assembleDebugAndroidTest
```

Если добавлен протокол или экран — обновите README/TESTING/PROTOCOLS и чек-лист.

## Тесты

- Новый алгоритм → unit-тест на границы и типичные случаи.
- Новый пакет → тест байтов заголовка и payload, включая chunking и переполнение.
- Новый HTTP-эндпоинт → MockWebServer: успех, ошибка статуса, битый JSON, таймаут.
- Не используйте `Thread.sleep`; для времени — инъекция часов.

## Безопасность и приватность

- Не логируйте кадры, содержимое экрана, токены и пароли.
- Не добавляйте аналитику/облако без явного решения владельца проекта.
- Не реализуйте обход DRM, secure surface и root-ограничений.
