# Протоколы и сетевые ограничения

Приложение использует только документированные интерфейсы WLED. Ниже — фактически реализованные
форматы и границы. Источники: [WLED DDP](https://kno.wled.ge/interfaces/ddp/),
[WLED UDP Realtime](https://kno.wled.ge/interfaces/udp-realtime/),
[WLED JSON API](https://kno.wled.ge/interfaces/json-api/).

## 1. Порты

| Назначение | Транспорт | Порт по умолчанию | Настраивается |
|---|---|---|---|
| WLED HTTP JSON API | TCP | 80 | да (`httpPort`) |
| DDP | UDP | 4048 | да (`outputPort`) |
| WLED UDP Realtime | UDP | 21324 | да (`outputPort`) |
| mDNS `_wled._tcp` | UDP multicast | 5353 | нет |
| Govee LAN: команды | UDP | 4003 (на лампе) | нет |
| Govee LAN: поиск | UDP multicast 239.255.255.250 | 4001 → ответ на 4002 | нет |

Порт **19446**, встречающийся в некоторых приложениях, не является универсальным для WLED и по
умолчанию не используется. Порт realtime задаётся в настройках устройства.

## 2. DDP (Distributed Display Protocol)

Реализация: `DdpPacketBuilder`. Заголовок — 10 байт, big-endian:

| Смещение | Размер | Поле | Значение в приложении |
|---|---|---|---|
| 0 | 1 | flags | `0x40` (version 1), последний пакет кадра — `0x41` (push) |
| 1 | 1 | sequence | счётчик пакета, переполняется через 255 |
| 2 | 1 | data type | `0x0B` — RGB888 |
| 3 | 1 | destination id | `1` |
| 4 | 4 | data offset | смещение в байтах: LED × 3 |
| 8 | 2 | data length | длина payload, ≤ 1440 |
| 10 | … | payload | R, G, B на каждый LED |

- Пакет содержит до **480 LED** (1440 байт payload).
- Кадр из 1000 LED → 3 пакета: offset 0/1440/2880, length 1440/1440/120, push только в последнем.
- RGBW (`0x1B`) не используется: приложение выводит RGB; для RGBW-прошивок WLED сам дополнит канал.
- Доставка UDP не гарантируется; DDP не имеет подтверждений.

Пример для двух LED `#FF0000`, `#00FF00`:

```text
41 00 0B 01 00 00 00 00 00 06 FF 00 00 00 FF 00
```

## 3. WLED UDP Realtime

Реализация: `WledUdpPacketBuilder`. Первый байт — тип протокола, второй — таймаут в секундах
(`0` — значение WLED по умолчанию; приложение отправляет `2`).

| Режим | Байт 0 | Формат | Ограничение |
|---|---|---|---|
| WARLS | `1` | `[1, timeout, index, r,g,b, index, r,g,b, …]` | 255 LED на пакет (index — 1 байт) |
| DRGB | `2` | `[2, timeout, r,g,b, r,g,b, …]` | один пакет на кадр, без адресации; ≤ 480 LED |
| DNRGB | `4` | `[4, timeout, startHi, startLo, r,g,b, …]` | 480 LED на пакет, start — 16 бит |

- Большие раскладки: **DNRGB** (несколько пакетов с offset) или DDP.
- DRGB с более чем 480 LED отклоняется на старте с `UNSUPPORTED_PROTOCOL`, а не отправляет
  обрезанный кадр.
- WLED выходит из realtime-режима, если пакеты не приходят дольше `timeout` секунд. Это же
  поведение освобождает контроллер, если приложение было убито.
- Пока WLED в realtime, его обычные эффекты/пресеты временно перекрываются. Приложение показывает
  предупреждение, если `/json/info` сообщает `live: true` до старта.

Пример DNRGB для 2 LED, timeout 2, старт 0:

```text
04 02 00 00 FF 00 00 00 FF 00
```

## 4. WLED HTTP JSON API

| Запрос | Назначение |
|---|---|
| `GET /json/info` | имя, версия (`ver`), количество LED (`leds.count`), `udpport`, `live` |
| `GET /json/state` | состояние (используется диагностикой, не обязателен для стрима) |
| `POST /json/state` | включение, яркость, тестовый цвет сегмента 0 |

Особенности клиента:

- таймауты: connect 3 с, read 4 с, call 6 с;
- лимит тела ответа 256 КиБ, иначе `PayloadTooLarge`;
- неизвестные JSON-поля игнорируются;
- ошибки типизированы: `Timeout`, `Unreachable`, `BadStatus`, `InvalidPayload`, `PayloadTooLarge`;
- отмена корутины отменяет HTTP-вызов.

HTTP-доступность и UDP-доставка проверяются отдельно: сеть может разрешать HTTP и блокировать UDP
(или наоборот). В диагностике есть отдельные кнопки.

## 5. Обнаружение

- mDNS/NSD: тип `_wled._tcp.`; WLED должен иметь включённый mDNS. Приложение держит
  `MulticastLock`, ищет 12 секунд и показывает найденные `host:port`.
- Ручное добавление: IPv4 или hostname (RFC 1123), без схемы и пути; порты 1–65535.
- Скан /24: запускается **только** пользователем после подтверждения. Проверяются адреса 1–254
  (кроме собственного), 24 параллельных HTTP-запроса, таймаут 1.2 с. Это не фоновое сканирование.
- IPv6 в MVP не поддерживается.

## 6. Зоны и несколько выходов

- `OutputPlanner` превращает конфигурацию в план: на каждый WLED-контроллер — список
  непересекающихся диапазонов LED (`ledOffset`, `ledCount`), на каждую лампу Govee — область экрана.
- DDP: каждый диапазон кодируется с собственным data offset (`(ledOffset + i) × 3` байт); флаг push
  ставится только в последнем пакете кадра контроллера, поэтому все зоны отображаются одновременно.
- WLED UDP: DNRGB использует start index = `ledOffset`; WARLS — индекс `ledOffset + i` (≤ 255);
  DRGB адресации не имеет, поэтому допускает только один диапазон с LED 0.
- Все выходы вычисляются из одного кадра и отправляются в одном такте конвейера.
- Keep-alive: если кадров нет дольше 1 с (статичная картинка), последний набор пакетов повторяется.
- При остановке на каждый WLED с доступным HTTP отправляется `POST /json/state {"live": false}`.
- Управление: `GET /presets.json` (ключ — id пресета, `"0"` пропускается), `GET /json/eff`,
  `{"ps": id}`, `{"on": true, "seg": {"fx": id}}` (объект `seg` применяется к выбранным сегментам).

## 7. Govee LAN API

Источник: Govee Developer Platform, «LAN API». Режим LAN Control включается для каждой лампы в
Govee Home и есть не на всех моделях.

| Команда | JSON |
|---|---|
| поиск | `{"msg":{"cmd":"scan","data":{"account_topic":"reserve"}}}` → 239.255.255.250:4001 |
| питание | `{"msg":{"cmd":"turn","data":{"value":1}}}` |
| яркость | `{"msg":{"cmd":"brightness","data":{"value":1..100}}}` |
| цвет | `{"msg":{"cmd":"colorwc","data":{"color":{"r":..,"g":..,"b":..},"colorTemInKelvin":0}}}` |

- Ответы на поиск приходят на UDP 4002 клиента. Это **единственное** место, где приложение слушает
  порт: только во время явно запущенного поиска (3 с), затем сокет закрывается.
- Команды не подтверждаются; приложение ограничивает частоту (≤ 10/с), пропускает почти одинаковые
  цвета и раз в 3 с повторяет текущий.
- Посегментный стрим (`razer`/`ptReal`) не опубликован официально и не используется: лампа
  показывает один цвет.

## 8. Не поддержано в этой версии

- **Hyperion/HyperHDR**: нет проверенного протокола/аутентификации и тестового стенда.
- **USB Adalight**: нет проверенного USB-serial пути и оборудования; добавлять фиктивную опцию
  запрещено.
- **RGBW**: вывод RGB; коррекция белого канала не реализована.
- **Звуковая реактивность** — не реализована.
- **Philips Hue Entertainment** (DTLS + сопряжение с мостом), **Nanoleaf**, **Yeelight**, **WiZ** — не
  реализованы; WiZ не имеет официально опубликованного локального API.

## 9. Ограничения доставки и DRM

- UDP не гарантирует порядок и доставку; при перегрузке возможны пропуски кадров.
- Ошибки считаются для каждого выхода отдельно: после 5 подряд выход ставится на паузу 1→2→4…15 с,
  при повторе адрес резолвится заново. Сессия завершается с `NETWORK_LOST`, только если на паузе все
  выходы.
- Захват экрана не получает DRM-защищённые поверхности. Чёрный кадр объясняется в UI; обход
  (root, перехват surface, HDMI-эмуляция) не реализуется.
